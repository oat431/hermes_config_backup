# Thai Technology and Computing Curriculum Research Notes

Use this reference when producing a research-only curriculum blueprint for Thai Career & Technology / computing topics across ป.1–ม.6. It records the source strategy and the durable curriculum distinctions found during the August 2026 research session.

## Curriculum anchor

The current Thai framework places Computing Science and Design & Technology in the **Science and Technology learning area (กลุ่มสาระการเรียนรู้วิทยาศาสตร์และเทคโนโลยี)** under the revised Basic Education Core Curriculum B.E. 2551 (2017 revision), especially standard **ว 4.2** for computational thinking, information technology, safe/responsible use, and ethics. The older label **Career and Technology (การงานอาชีพและเทคโนโลยี)** is useful as a user-facing parent category, but do not describe these modules as the current ICT strand of that old learning area. IPST's page explains the transition and links the official curriculum materials.

## Grade-band progression for blueprints

This is a synthesis for organizing notes, not a substitute for a school's local course plan. Schools may distribute indicators differently, so use grade bands rather than claiming that every school teaches an identical unit sequence.

### ป.1–3: foundations and safe participation

- Recognize common devices and their purposes; operate a mouse/keyboard/touch interface; care for equipment.
- Represent a simple procedure or solution using pictures, symbols, or short text (ขั้นตอน, อัลกอริทึม).
- Use unplugged activities and beginner block programming; follow sequences; begin noticing and correcting errors (ตรวจหาข้อผิดพลาด).
- Create, classify, search, store, and retrieve simple data; by ป.3, use the Internet for knowledge search and present processed information with suitable software.
- Follow classroom agreements and basic safe-use habits; do not share personal information or interact with unsafe content without adult help.

### ป.4–6: productive use, evaluation, and collaboration

- Apply logical reasoning (เหตุผลเชิงตรรกะ), decompose tasks, design algorithms, and build/debug block programs.
- Search online with better queries; compare sources and judge basic credibility (ความน่าเชื่อถือของข้อมูล).
- Collect, evaluate, organize, and present information with multiple software tools or online services; communicate and collaborate.
- Understand rights and duties, etiquette, authorship, permission, and how to report inappropriate content or people.
- Treat privacy, account security, respectful communication, and source attribution as part of ordinary digital work rather than a separate warning lesson.

### ม.1–3: abstraction, systems, apps, and critical media use

- Move from concrete procedures to abstraction (การคิดเชิงนามธรรม), algorithms, variables (ตัวแปร), conditions (เงื่อนไข), loops (การวนซ้ำ), functions (ฟังก์ชัน), testing, and debugging.
- Collect primary data, process it, evaluate quality, and present it for a stated purpose using software or Internet services.
- Explain basic computer-system components and communication technology; connect hardware, software, networks, data, and users.
- Build or plan an application and integrate computing with another subject; by ม.3, assess source credibility, media framing, misinformation, and effects of false information.
- Use technology responsibly; cover copyright, licensing, fair use, privacy, security, and the Computer-Related Crime Act at an age-appropriate level.

### ม.4–6: integrated projects and information responsibility

- Apply computational thinking in a creative project integrated with another subject; define a problem, model it, develop a solution, test it, evaluate evidence, and iterate.
- Use a complete data workflow: collection, cleaning/processing, analysis, visualization/presentation, evaluation, and communication of limitations.
- Critically evaluate information and media, detect misleading or false claims, document sources, and explain social consequences.
- Apply safe and socially responsible technology use, Thai computer-law awareness, privacy protection, intellectual property, copyright, and ethical publication.
- Treat school assignments as authentic portfolio work: a brief, data plan, prototype or program, test evidence, reflection, and source/rights record.

## Research workflow and tool lessons

1. Start with the IPST curriculum hub, not broad Thai search queries. The IPST `/cs` page exposes direct official PDFs, textbook links, and grade resources.
2. Batch independent source lookups, then inspect the strongest official pages. Do not continue issuing repeated near-identical searches when the backend returns irrelevant results.
3. If `web_extract` reports that the configured backend is search-only, switch to a direct URL retrieval method such as `terminal` with `curl -k -L -A 'Mozilla/5.0'`, then parse the returned HTML or PDF. This is a recovery path, not a claim that browser or extraction tools are permanently unavailable.
4. On the Windows Git Bash environment, use the working directory or a Windows-visible path for temporary downloads. A Unix `/tmp` path may not be visible to the Windows Python interpreter; avoid unnecessary temporary files and remove them after inspection.
5. For IPST PDFs, `pdftotext` may expose page structure but not all Thai glyphs. Cite the official PDF and use the accessible IPST HTML hub/Project 14 pages to corroborate grade and resource identity. Do not invent verbatim quotations from garbled extraction.
6. Keep legal statements educational and high-level. Link to PDPC and MDES official portals; verify the current law/version before teaching detailed legal advice.

## Blueprint quality gates

- State that the five topics are cross-cutting implementation modules, not necessarily five official named IPST strands.
- Include all four grade bands and show progression, not just a list of skills.
- Separate operational skill from safety, ethics, privacy, and source evaluation.
- Include Thai terminology in parentheses in English narrative.
- Give one age-appropriate hands-on project per topic with an observable artifact.
- Cite IPST first, then use international frameworks/tool documentation as supplements.
- Keep research-only requests research-only: do not create or modify vault files unless the user asks explicitly.
