# CouchDB — Homelab Configuration

> Verified on CouchDB 3.5.2, Docker 29.6.2, Panomete homelab.

## Container Details

| Item | Value |
|------|-------|
| Image | `couchdb:3` |
| Container | `local-couchdb` |
| Port | `127.0.0.1:5984` |
| Compose | `~/database/couchdb/compose.yml` |
| Secrets | `~/database/couchdb/.env` (auto-generated password + secret) |
| Network | `db-network` |

## Compose File

```yaml
services:
  couchdb:
    container_name: local-couchdb
    image: couchdb:3
    environment:
      COUCHDB_USER: ${COUCHDB_USER:-admin}
      COUCHDB_PASSWORD: ${COUCHDB_PASSWORD:-couchdb}
      COUCHDB_SECRET: ${COUCHDB_SECRET}
    volumes:
      - couchdb_data:/opt/couchdb/data
      - couchdb_config:/opt/couchdb/etc/local.d
    ports:
      - "127.0.0.1:5984:5984"
    restart: unless-stopped
    networks:
      - shared-network
    healthcheck:
      test: ["CMD-SHELL", "curl -sf http://localhost:5984/ || exit 1"]
      interval: 15s
      timeout: 5s
      retries: 3

volumes:
  couchdb_data:
  couchdb_config:

networks:
  shared-network:
    external: true
    name: db-network
```

## Placement Convention

CouchDB lives in `~/database/couchdb/` alongside the other shared databases (postgres, valkey, mongodb). It joins `db-network` so containers can reach it at `couchdb:5984`.

## Obsidian LiveSync Integration

LiveSync is the primary consumer of CouchDB. Key notes:

1. **MongoDB CANNOT replace CouchDB** — LiveSync uses PouchDB client-side, which only speaks CouchDB replication protocol. No MongoDB adapter exists.

2. **Backend options for LiveSync:**
   - **CouchDB** (recommended — real-time sync, conflict resolution, live changes)
   - Object Storage (S3/MinIO/R2) — newer mode, no real-time push
   - Peer-to-Peer (WebRTC) — direct device-to-device

3. **LiveSync setup requires (after CouchDB running):**
   - Create database (e.g. `obsidian-livesync`)
   - Create non-admin user for the plugin
   - Enable CORS (so Obsidian app can reach CouchDB) — see Step 5 for the master-switch gotcha
   - Nginx reverse proxy (`obsync.panomete.com` → `127.0.0.1:5984`)

## LiveSync Provisioning (API — after CouchDB is running)

Run these once to prepare CouchDB for Obsidian LiveSync. All via curl REST API.

### Step 1 — Create system databases

```bash
source ~/database/couchdb/.env
curl -X PUT -u ${COUCHDB_USER}:${COUCHDB_PASSWORD} http://127.0.0.1:5984/_users
curl -X PUT -u ${COUCHDB_USER}:${COUCHDB_PASSWORD} http://127.0.0.1:5984/_replicator
curl -X PUT -u ${COUCHDB_USER}:${COUCHDB_PASSWORD} http://127.0.0.1:5984/_global_changes
```

Without `_users`, user creation fails with `"Database does not exist."`

### Step 2 — Create the LiveSync database

```bash
curl -X PUT -u ${COUCHDB_USER}:${COUCHDB_PASSWORD} http://127.0.0.1:5984/obsidian-livesync
```

### Step 3 — Create a non-admin user

```bash
curl -X PUT -u ${COUCHDB_USER}:${COUCHDB_PASSWORD} \
  -H "Content-Type: application/json" \
  -d '{"_id":"org.couchdb.user:USERNAME","name":"USERNAME","type":"user","roles":[],"password":"PASSWORD"}' \
  http://127.0.0.1:5984/_users/org.couchdb.user:USERNAME
```

### Step 4 — Grant database access

```bash
curl -X PUT -u ${COUCHDB_USER}:${COUCHDB_PASSWORD} \
  -H "Content-Type: application/json" \
  -d '{"admins":{"names":[],"roles":[]},"members":{"names":["USERNAME"],"roles":[]}}' \
  http://127.0.0.1:5984/obsidian-livesync/_security
```

Without this, the user authenticates but gets `"You are not allowed"` when accessing the DB.

### Step 5 — Enable CORS (THE gotcha step)

CouchDB 3.x CORS has a **master switch that defaults OFF**:

```
[chttpd] enable_cors = false   ← DEFAULT
```

Without it, every `[cors]` setting is silently ignored — no `Access-Control-*` headers on any response, and OPTIONS preflights fall through to auth and return 401. This exact symptom ("The request was successful by API. But the native fetch API failed!") took a full debugging session to trace to this one key.

Config API expects **raw JSON strings** (not objects with `"value":`). Wrong format causes `"a JSON string expected"`:

```bash
BASE=http://127.0.0.1:5984/_node/_local/_config

# 1. MASTER SWITCH — without this nothing else matters
curl -X PUT -u admin:PASS -H "Content-Type: application/json" -d '"true"' $BASE/chttpd/enable_cors

# 2. Explicit origins — see rule below
curl -X PUT -u admin:PASS -H "Content-Type: application/json" \
  -d '"app://obsidian.md,capacitor://localhost,http://localhost,https://localhost,https://obsync.panomete.com"' \
  $BASE/cors/origins

curl -X PUT -u admin:PASS -H "Content-Type: application/json" -d '"true"' $BASE/cors/credentials
curl -X PUT -u admin:PASS -H "Content-Type: application/json" -d '"accept,authorization,content-type,origin,referer,x-requested-with"' $BASE/cors/headers
curl -X PUT -u admin:PASS -H "Content-Type: application/json" -d '"GET,PUT,POST,HEAD,DELETE"' $BASE/cors/methods
```

**CORS rules learned the hard way:**

1. **`enable_cors` master switch** — `[chttpd] enable_cors = true` is required; default false. CORS silently does nothing without it (verify via `curl -s .../_node/_local/_config/chttpd`).
2. **`origins = *` + `credentials = true` conflict** — CouchDB logs `config: [cors] credentials set to false for reason nil` and silently disables credentials. Use an explicit origin list (must include `app://obsidian.md` for the Obsidian desktop Electron app, `capacitor://localhost` for mobile).
3. **Config values live in TWO places** — the runtime config DB (set via `_config` API, applied live) AND the ini files. The official docker image regenerates `docker.ini` at startup from runtime config — edit BOTH for persistence.
4. **`docker cp` breaks config writes** — files copied into the container get host UID (1000), but CouchDB runs as UID 5984. Every config PUT then fails with `{"error":"bad_request","reason":"eacces"}`. Fix: `docker exec local-couchdb chown 5984:5984 /opt/couchdb/etc/local.d/docker.ini`.
5. **Never delete a tracked ini file at runtime** — deleting `11-cors.ini` crashed the config server (`badrpc ... Couldn't find server configuration file`), making ALL config ops fail until container restart. Edit files, don't delete them mid-flight.

**Verify (the test that actually matters):**

```bash
# OPTIONS preflight with Obsidian's real origin — expect 204 + headers
curl -si -X OPTIONS -H "Origin: app://obsidian.md" \
  -H "Access-Control-Request-Method: PUT" \
  -H "Access-Control-Request-Headers: authorization" \
  https://obsync.panomete.com/obsidian-livesync | grep -i "HTTP/\|access-control"
# → HTTP/1.1 204 No Content
#   access-control-allow-origin: app://obsidian.md
#   access-control-allow-credentials: true
```

If preflight returns **401**, CORS is still off (enable_cors missing or origin not listed).

**Nginx stays a pure proxy** — CouchDB emits CORS headers natively; adding them in Nginx produces duplicate `Access-Control-*` headers and browsers reject the response. Keep the Nginx block simple (proxy_pass + headers + `proxy_buffering off` for the long-poll `_changes` feed).

### Step 6 — Verify user access

```bash
curl -s -u USERNAME:PASSWORD http://127.0.0.1:5984/_session    # should return "ok": true
curl -s -u USERNAME:PASSWORD http://127.0.0.1:5984/obsidian-livesync  # should return DB info
```

## Obsidian LiveSync Plugin Setup (Pitfall)

### The wizard has TWO paths — first device must use MANUAL

The Self-hosted LiveSync plugin uses an onboarding **wizard**, not manual settings fields. On the first device connecting to a fresh server:

1. Open the "Welcome to Self-hosted LiveSync" notice
2. Choose `I am setting this up for the first time`
3. On **Connection Method**, choose:
   - `✅ Configure a remote manually` — THIS is where URI/username/password/database fields appear
   - `❌ Use a Setup URI (Recommended)` — asks for URI + passphrase only (for additional devices)

**Pitfall:** The Setup URI option does NOT show server credential fields. If you're the first device and the server is empty, there's no Setup URI yet — you MUST choose manual config. The wizard recommends Setup URI, but that's only viable after device 1 is synced.

### Two passphrases — don't confuse them

| Passphrase | Protects | When needed |
|------------|----------|-------------|
| **Vault encryption passphrase** | Note content (E2EE) on the server | Set on device 1, reused on all devices |
| **Setup URI passphrase** | The Setup URI link (connection settings) | Only when adding devices via Setup URI |

These are different passwords. The Setup URI passphrase decrypts the connection settings blob; the Vault passphrase decrypts the actual notes. Losing the Vault passphrase = data unrecoverable.

### Adding additional devices

After device 1 works:
1. Command Palette → `Self-hosted LiveSync: Copy settings as a new Setup URI`
2. Enter a new passphrase (the Setup URI passphrase)
3. On device 2: paste URI + passphrase → choose `Read replica` mode → fetch from server

## User Management for Shared Vaults

For multi-user vaults, each person needs their own CouchDB user (Steps 3-4 above repeated per user). Admin guide lives in Obsidian at `F:\obsidian_note\oralita_md\Quick Note\CouchDB User Management.md`. End-user connection guide at `Obsidian LiveSync Connection.md`.

When updating `_security` members via API, the PUT **replaces the entire members list** — include all existing usernames, not just the new one.

## What CouchDB IS (for context)

CouchDB is NOT like PostgreSQL/MongoDB (binary wire protocol). It's an **HTTP server that stores JSON documents**. Every operation is a plain HTTP request:

```
GET    /db/doc_id     ← fetch
PUT    /db/doc_id     ← save
GET    /db/_all_docs  ← list
POST   /db/_find      ← query (Mango)
```

Port 5984 IS the database port — it just happens to speak HTTP. The admin UI (Fauxton) at `/_utils/` is a web app making HTTP calls to the same port. Obsidian LiveSync connects via HTTP fetch — no database driver needed.
